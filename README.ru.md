# Lingua CLI

[English](README.md) | Русский

Консольный проект на Python для перевода текста и поиска информации об английских словах.

## Статус проекта

В разработке. Настроена упаковка для команды `lingua-cli` и реализован базовый
разбор аргументов со справкой `--help`. Подкоманды `translate` и `word`,
интеграции с API и форматированный вывод пока не реализованы.

## Планируемые возможности

- Перевод слов и фраз на выбранный язык.
- Автоматическое определение исходного языка через API переводчика.
- Получение определений, фонетической транскрипции и частей речи английских слов.
- Отображение примеров использования, синонимов и антонимов при наличии данных.
- Оформление результатов с помощью панелей и таблиц Rich.
- Обработка некорректного ввода, отсутствующего API-ключа, HTTP-ошибок и сетевых таймаутов.

## Технологии

- **Python** — логика приложения и разделение кода на модули.
- **argparse** — аргументы командной строки и подкоманды; входит в стандартную библиотеку.
- **requests** — HTTP-запросы к внешним API.
- **python-dotenv** — загрузка локальных настроек из файла `.env`.
- **rich** — оформление вывода в терминале.

Для словаря будет использоваться Free Dictionary API. Сервис перевода пока не выбран.

## Локальная установка

Выполни следующие команды в PowerShell из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\Activate.ps1
```

Если `.venv` уже существует, используй это окружение и пропусти его создание.
Установка в режиме разработки (`-e .`) устанавливает проект и его зависимости,
сохраняя связь с исходными файлами. Изменения существующего Python-кода доступны
при следующем запуске; после изменения настроек упаковки повтори установку.

После активации окружения выведи справку по команде:

```powershell
lingua-cli --help
```

Для использования короткой команды активируй `.venv` в каждой новой сессии
терминала. Также можно вывести справку без активации из папки проекта:

```powershell
.\.venv\Scripts\lingua-cli.exe --help
```

На данном этапе запуск `lingua-cli` без аргументов завершается без вывода в терминал.

## Планируемая настройка

Модуль перевода будет читать `TRANSLATOR_API_KEY` из переменных окружения
или локального файла `.env`. Используй `.env.example` как образец настроек:

```dotenv
TRANSLATOR_API_KEY=your_api_key_here
```

Храни настоящий ключ в `.env`, который исключён из Git. Файл `.env.example`
содержит только заглушку. Инструкция по получению ключа появится после выбора
сервиса перевода.

## Планируемое использование

Эти команды описывают будущий интерфейс и пока не реализованы:

```powershell
lingua-cli translate "Hello world" --to ru
lingua-cli word hello
```

## Текущая структура проекта

```text
lingua-cli/
├── main.py              # Точка входа в приложение
├── pyproject.toml       # Настройки упаковки и команды CLI
├── .env.example         # Образец настроек
├── .gitignore           # Локальные файлы, исключённые из Git
├── requirements.txt     # Сторонние зависимости
├── lingua_cli_TZ.md      # Техническое задание на русском языке
├── README.md            # Документация на английском языке
└── README.ru.md         # Документация на русском языке
```

По мере разработки модули `translator.py` и `dictionary.py` будут отвечать
за обращения к API и разбор ответов, а `config.py` — за настройки.
В `main.py` будут находиться разбор аргументов, вызов нужных функций и вывод результатов.

## Учебные цели

Этот проект для портфолио посвящён работе с HTTP API, разбору JSON,
аутентификации при обращении к API, обработке ошибок и разделению
небольшого консольного приложения на модули Python.

Требования и сценарии проверки описаны в [техническом задании](lingua_cli_TZ.md).
